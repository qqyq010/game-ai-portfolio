# Git 개편에 적용한 검수 예시

포트폴리오를 개편할 때 첫 화면에서 출시작과 시연을 바로 찾을 수 있게 하려고 했습니다. 각 사례에서는 당시 확인한 기록까지 열 수 있는지도 봤습니다. 이전 README와 바꾼 파일을 맞춰 보고 이미 공유한 주소에서 문서가 열리는지 확인했습니다. 시연 영상과 PDF도 열어 봤습니다.

## 첫 화면에서 출시작과 시연 찾기

이전 README에서는 PDF를 바로 열 수 있었습니다. 첫 화면에 출시 페이지와 공식 영상 링크를 추가했습니다. 같은 화면에서 quality-pass 문서도 찾을 수 있게 했습니다. 공식 영상은 Steam 페이지의 영상 구역으로 연결했습니다.

## 예전에 공유한 사례에서 이어 읽기

기존 Coin Survivor 문서에는 무기 판매와 초반 골드를 설명하는 소제목이 있었습니다. 그 주소로 들어갔을 때도 새 판매 확인표와 밸런스 사례를 찾을 수 있도록 연결했습니다. 미리보기에서 옛 골드 주소를 열고 새 사례까지 넘어가는 것을 확인했습니다.

## Steam 게임 수에 기준 적기

이전 PDF에는 10월에 보유한 게임 수가 적혀 있었고 11월 지원 당시 라이브러리의 수는 달랐습니다. 9월 기록은 플레이 시간이 표시된 항목만 셌습니다. 각각 언제 무엇을 셌는지 적고 9월 목록의 162개 항목을 대조했습니다.

## 휴대전화 화면에서 줄바꿈 보기

폭 390px에서는 제목의 마지막 글자와 PDF 링크가 다음 줄로 넘어갔습니다. 이 예시의 표도 한 칸 안에서 줄이 지나치게 잘게 끊겼습니다. 첫 화면의 제목과 링크를 줄이고 여기서는 소제목 아래에 문단으로 설명했습니다. Git에서 발견한 줄 끝 공백도 고친 뒤 다시 미리보기를 열었습니다.

## 같은 개편 내용을 다시 확인하기

1. 첫 화면에서 STOVE 출시 페이지와 공식 영상을 열어 봅니다. PDF도 열리는지 확인하고 AI 협업 항목에서 검수 방법과 이 예시를 찾아봅니다.
2. [예전 골드 사례 주소](../../cases/coin-survivor.md#초반-골드로-어떤-선택이-가능한가)를 열고 새 사례로 넘어가 봅니다. PDF와 시연도 열리는지 확인합니다.
3. 개편 전후 커밋을 비교해 어떤 파일을 바꿨는지와 공백 오류가 있는지를 확인합니다.

```text
git diff --name-status 72fa808 fdb0a11
git diff --check 72fa808 fdb0a11
```

위 검수에서는 로컬 저장소의 변경과 문서 미리보기를 확인했습니다. 게임에서 무엇을 실행해 봤는지는 각 프로젝트에 당시 기록을 남겼습니다.
