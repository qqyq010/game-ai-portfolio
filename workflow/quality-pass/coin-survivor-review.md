# 게임 작업에서 완료 보고를 다시 읽은 예시

Coin Survivor에서 먼저 해야 할 일은 합성이 아니라 아이템을 클릭해 집고 놓는 조작이었습니다. 당시 대화와 조작의 Play Mode 기록을 2026년 11월 24일에 다시 열어 현재의 quality-pass 순서로 대조했습니다.

## 요구와 수정 범위부터 확인

상점과 인벤토리에서 조작을 고치고 기존의 구매·판매를 유지하기로 했습니다. 변경 목록에 팀원 쪽 전투 파일이 보이자 원래 정한 범위와 맞는지 다시 살펴 달라고 했습니다. 클릭 조작을 마쳤다는 보고 뒤에는 제가 보고 있던 코드에 집은 위치를 기록하는 값과 바깥쪽 클릭 처리가 보이는지 다시 물었습니다. 당시 화면과 비교한 첨부 파일의 정확한 버전은 재검수 자료에서 확정할 수 없었습니다.

## 게임에서 확인한 근거

- **배치 실패**는 여러 아이템과 겹쳤을 때 들고 있던 아이템이 제자리로 돌아가는지로 확인했습니다.
- **기존 판매**는 아이템을 든 채로 상점을 눌렀을 때 판매 팝업이 열리고 취소하면 제자리로 돌아가는지 봤습니다.
- **기존 구매**는 같은 클릭에서 구매까지 되지 않는지, 아이템을 손에 들지 않았을 때는 평소처럼 구매되는지를 따로 봤습니다.

## 이번 검수에서 고친 표현

처음 사례 문장은 아이템을 들고 있으면 ‘추가 구매가 막힌다’고만 적었습니다. Play Mode 기록에는 판매 팝업이 열리면서 **같은 클릭에는 구매가 실행되지 않는 것**까지 남아 있었습니다. 정상적으로 남겨야 하는 판매와 막아야 하는 동작을 [조작 사례](../../projects/coin-survivor/inventory-pick-and-place.md)에 구분해 넣고, 수정한 문장을 당시 최종 확인 항목과 다시 대조했습니다.

이번에는 당시 대화와 작업·실행 기록을 다시 대조했습니다. 위에 적은 게임 동작은 4월의 Play Mode 기록에 근거합니다.
