# quality-pass로 작업이 끝났는지 확인하기

Codex가 작업을 마쳤다고 하면 처음에 뭘 요청했는지와 실제로 뭘 바꾸고 검사했는지를 맞춰 봅니다. 매번 이 순서를 설명하는 대신 같은 방법으로 검토할 수 있도록 제가 만든 Codex Skill입니다. 아래 순서와 요청문을 써서 같은 방식으로 확인할 수 있습니다.

## 작업이 끝난 뒤 확인하는 순서

1. **처음 요청을 꺼냅니다.** 어떤 결과가 나와야 끝난 것인지 적습니다. 수정해도 되는 파일과 같이 볼 자료도 넣습니다.
2. **바뀐 내용과 검사 결과를 붙입니다.** 변경 파일 목록이나 전후 비교를 넣습니다. Unity 작업이라면 빌드 결과와 직접 플레이한 기록을 각각 붙입니다.
3. **요구마다 어디에서 확인했는지 묻습니다.** 반영된 내용은 파일이나 검사 결과를 가리키게 합니다. 범위 밖에서 바뀐 곳과 해 보지 못한 검사도 적게 합니다.
4. **고칠 항목을 정하고 같은 방법으로 다시 확인합니다.** 수정한 뒤 처음 요구가 충족됐는지 다시 봅니다.
