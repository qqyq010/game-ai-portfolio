# Codex 작업 방식은 어떻게 바뀌었나

## 범위와 완료 조건부터

목표, 관련 파일, 수정 범위, 완료 조건을 정합니다. 팀원 코드에는 먼저 경계를 둡니다. Unity 버그의 경우 재현 조건을 적어 조사부터 맡기고, 수정 파일과 빌드 결과를 확인한 뒤 Play Mode에서 게임 동작을 직접 확인합니다. 빌드 성공과 실제 플레이 확인은 기록에서 따로 둡니다.

## 반복 업무를 다시 쓰는 방법

6월에는 전역 지침을 적용했다고 기록했고, 공통 작업 규칙과 프로젝트 파일도 따로 정리했습니다. 프로젝트 수정 범위는 프로젝트 규칙에, 다시 참고할 선호와 제한은 Memory에 남겼습니다. 회의 전사는 Skill과 스크립트로 정리했습니다. 생성 및 형식 검증 기록은 있으나 전사 정확도나 전체 작업의 시간 변화는 계량하지 않았습니다.

## 검토를 나눴을 때

일부 평가에서는 사례 작성, 버전별 검토, 결과 비교를 AI 작업에 나눠 맡겼습니다. 개선 지침을 기존판과 가린 상태로 비교했고, 첫 비교가 동률이어서 실제 작업 자료로 범위를 넓혔습니다. 그 비교에서도 판단력 차이는 확인하지 못해 측정된 분류 변화만 남겼습니다. 평가자는 같은 모델 계열이어서 독립적인 사람 평가 결과로 볼 수 없습니다.

지원 자료 조사에서는 메인과 보조 작업 세 개를 운영했으나 원문 확인을 끝낸 자료의 진척이 기대에 못 미쳤습니다. 한 대화로 돌아가 수집·분석·검토·분류·재분석을 순서대로 이어갔습니다. 다음에는 짧은 구간에서 완료 건수와 제가 검수하는 데 쓴 시간을 함께 확인하겠습니다.
