# 만들었던 기능을 제 말로 설명해 보기

Unity와 C#으로 기능을 완성했지만, 기술 면접에서 왜 그렇게 동작하는지 제 말로 설명하기 어려웠습니다. 8월 24일 기초 진단에서 개념 13번까지 직접 답하고 기초 학습을 시작했습니다. 멈췄던 항목을 다시 설명하고 실습 결과를 확인하는 일이 남았습니다.

## 기존 프로젝트를 놓고 다시 설명해 볼 질문

- **EscapeRoom**에서 적에게 들키면 위치까지 되돌리고, 일반 퍼즐을 틀리면 입력만 돌려준 이유는 무엇인가. [실패 원인별 설정과 코드](../projects/escape-room/failure-and-retry.md)
- **Fisher**에서 가방 화면의 값과 저장값이 다를 때 확인할 순서를 어떻게 정할까. [씬 전환 뒤 실제 확인 기록](../projects/fisher-idle-rpg/evidence/bag-state-checks.md)

개념을 실제 동작에 연결해 설명하려는 예입니다. EscapeRoom의 자동 검사와 Fisher의 당시 팀 검증은 프로젝트 실행 기록이며, 개인 학습 진도는 진단·실습·재시험 기록을 기준으로 봅니다.

게이머로서 본 규칙을 판단 기준으로 옮긴 작업도 있습니다. 깨비 덱 연구실에서는 도술을 사용한 영상에서 충전 뒤 쿨타임 숫자를 보고, 어떤 조건에서 덱을 비교할지 정했습니다. 이 작업은 영상 관찰과 모델 실험을 따로 설명할 수 있는 사례입니다. [충전 도술을 비교한 과정](../game-tools/kkaebi-deck-lab/README.md)
