# 만들었던 기능을 제 말로 설명해 보기

Unity와 C#을 쓰며 기능을 완성했지만, 기술 면접에서 왜 그렇게 동작하는지 제 말로 설명하기 어려웠습니다. 기초 진단 문제에 직접 답해 보며 익숙한 용어와 자신 있게 설명할 수 있는 원리가 서로 다르다는 걸 알았습니다.

요즘은 배운 기능을 작은 예제로 다시 구현해 보고, 선택한 이유와 실패 조건까지 설명하는 연습을 합니다. 가령 EscapeRoom의 복구 코드에서는 아래 세 가지를 차례로 짚을 수 있습니다.

1. 실패 화면이 나오는 동안 입력을 잠그면 어떤 중복 조작을 막을 수 있나.
2. 복구 처리를 하는 곳과 잠금을 푸는 곳을 어떻게 나눴나.
3. 플레이어가 다시 움직일 수 있는지는 어떤 실행으로 확인했나.

8월에 기록으로 남은 학습은 기초 진단 첫 시도와 학습 시작입니다. [EscapeRoom 자동 검사](../projects/escape-room/evidence/play-mode-checks.md)는 별도 시점에 프로젝트를 실행한 결과입니다. [복구 코드에서 확인할 부분](../projects/escape-room/code/failure-recovery.md)
