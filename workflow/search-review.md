# 검색 도구를 검토하고 채택 범위를 정한 사례

개인 작업 공간에서 자료를 찾을 때 실제로 쓸 수 있는 환경과 업무가 먼저라고 기준을 정했습니다. 비교와 코드 변경은 AI가 맡았고, 저는 결과를 보고 유지할 범위를 정했습니다.

| 판단한 문제 | 비교·대응 | 확인한 결과 |
| --- | --- | --- |
| 다음 작업 검색에서 과거 설계가 먼저 나옴 | 현재 안내에 누락된 검색 별칭 두 개 추가 | 고정 검색 검사에서 64/65 → 65/65. 증가한 것은 이 고정 검사 한 건입니다. |
| Kiwi로 기존 검색 보완 | 못 찾던 자료를 더 찾는지, 오탐이 생기는지 비교 | 기존 누락을 메우지 못하고 새 오탐이 생겨 미채택 |
| MiniLM 유사도 비교 | 데이터와 입력을 준비한 뒤 로컬 환경에서 시험 | 메모리 조건 때문에 중단. 성능 개선 미확인 |
| OCR 후보 | 최소 사례를 준비 | 실제 인식 개선은 추가 확인이 필요한 단계 |

‘다음 작업’이나 승인 상태처럼 맞아야 하는 정보는 검색 순위만으로 결정하지 않고 현재 작업 기록을 확인하도록 했습니다.
