# 아이템을 내려놓을 수 없을 때

상점과 인벤토리에는 합성도 들어갈 예정이었습니다. 먼저 아이템을 클릭해 들고 내려놓는 동작이 안정되어야 합성 조건도 제대로 볼 수 있다고 판단했습니다. 그래서 합성은 뒤로 미루고 상점과 인벤토리 안에서만 조작을 손보는 계획을 정했습니다.

## 완료 보고를 받고 다시 확인한 부분

Obsidian에서 Markdown 계획을 읽으며 범위를 좁혔습니다. Codex가 구현을 진행하는 동안 변경 목록에 팀원이 맡은 전투 쪽 파일도 보였습니다. 해당 변경을 다시 확인하고 범위를 맞춰 달라고 요청했습니다.

클릭 조작을 마쳤다는 보고를 받았을 때도 제가 보고 있던 코드와 설명이 맞는지 다시 물었습니다. 아이템을 집은 위치, 인벤토리 밖 클릭, 판매 팝업을 항목으로 나누고 현재 파일부터 읽어 달라고 했습니다. 이때 비교한 첨부 화면의 버전은 당시 기록에서 확정할 수 없습니다.

## 제가 확인한 동작

| 상황 | 당시 Play Mode 기록 |
| --- | --- |
| 3×3 아이템의 중앙과 가장자리를 각각 집음 | 두 경우 모두 아이템 중심이 마우스를 따라감 |
| 1×3 무기를 집거나 아이템 하나 위에 놓음 | 무기 중심을 기준으로 잡았고, 한 개와 겹친 경우 자리를 바꾸고 그 아이템을 집음 |
| 여러 아이템과 겹쳐 놓을 곳이 없음 | 들고 있던 아이템이 사라지지 않고 제자리로 돌아감 |
| 아이템을 들고 상점을 클릭함 | 판매 팝업이 뜨고 같은 클릭에서 구매가 실행되지 않음. 판매를 취소하면 아이템이 제자리로 돌아감 |
| 아이템을 들고 있지 않은 상태에서 구매함 | 평소대로 상점 구매가 됨 |

이 기록을 남길 때는 합성 구현을 뒤로 미뤘습니다. 일단 어떤 경우에 움직이고 어디로 돌아오는지 확인할 수 있어야, 다음에 합성을 넣을 때 조작과 합성 중 어디서 문제가 생겼는지 좁힐 수 있습니다.
