# Star Rail Lab

개인 프로젝트에서 게임의 장비 선택지를 비교할 때 어떤 입력이 필요한지 재정의한 사례입니다.

## 처음 결과에서 빠진 조건

초기 결과가 보유 캐릭터와 장비, 콘텐츠 조건에 맞지 않다고 판단했습니다. 공식 참고자료와 문제 화면, 스캔 중단 로그를 제공하고, 어떤 보유 정보와 콘텐츠 조건을 반영해야 하는지 다시 정리했습니다. 구현 후에도 결과가 그 목적에 맞는지 살펴 피드백했습니다.

## 사람과 AI의 역할

저는 비교 목적과 요구사항을 정하고 결과를 확인했습니다. Codex는 코드 작성과 수정을 맡았습니다. 사례에서 확인한 코드 발췌에는 입력이 바뀌면 이전 결과를 지우고, 늦게 도착한 과거 요청의 응답을 무시하며, 계산 자료의 식별값을 확인하는 처리가 포함됩니다.

## 검증 범위

| 질문 | 확인된 범위 |
| --- | --- |
| 지금 어디까지 비교하는가 | 고정된 파티에서 한 캐릭터의 장비 후보를 비교합니다. |
| 입력 변경은 어떻게 다루는가 | 이전 결과 정리와 늦게 도착한 응답의 처리 로직을 코드 기록에서 확인했습니다. 검사 사례는 문서에 남아 있으며 실행 원문 로그는 확보하지 못했습니다. |
| 화면 피해량은 무엇인가 | 모델 계산값입니다. 실제 게임 측정값과의 대조는 미완료입니다. |
| 목표에서 남은 기능은 무엇인가 | 계정 연동과 보유 자원 기반 다중 파티 구성이 남아 있습니다. |

### 입력이 바뀔 때 확인할 조건

| 상황 | 기대 동작 | 근거 |
| --- | --- | --- |
| 기존 결과가 표시된 상태에서 장비 조건 변경 | 이전 조건의 결과를 비우고 새 입력의 결과를 기다림 | 코드 발췌의 결과 초기화 처리 |
| 조건 변경 전 요청이 뒤늦게 완료 | 늦게 도착한 응답이 새 결과를 덮어쓰지 않음 | 코드 발췌의 이전 응답 제외 처리 |
| 계산 자료를 읽어 비교 실행 | 사용 중인 계산 자료의 식별값을 확인 | 코드 발췌의 식별값 비교 처리 |

표는 구현 기록을 바탕으로 검토할 조건을 정리한 것입니다. 실제 환경에서 위 순서를 독립적으로 다시 실행한 기록은 확보하지 못했습니다.
